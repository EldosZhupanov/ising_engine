# EXP001: conditional response elimination × cross-curvature refinement

Status: binding on commit, before prototype code or candidate result data. Date 2026-09-11. Independent of RC-027; none of its data/seeds are inspected or used. Scope is an isolated exploratory mechanism experiment, not production integration or a universal optimizer claim.

## Hypotheses and treatment

H01 predicts that eliminating conditional interiors reduces residual search dimension and end-to-end cost on low-boundary graphs. H07 predicts that a measurable fraction of production 1-opt endpoints admit improving edge-pair moves. The full factorial isolates A (eliminate degree 0/1), B (eliminate degree exactly 2), C (joint pair-descent refinement). Arms are all bitmasks 0..7: baseline, A, B, A+B, C, A+C, B+C, A+B+C. Elimination iterates to a fixpoint under enabled rules. Reconstruct in reverse order. C runs after EVERY completed Ultimate call, on the original model after lifting, before incumbent comparison. All arms receive the same explicit full-variable 1-opt restoration after lifting (production polish only covers free variables); its work and improvement are recorded separately. C then alternates best improving pair with 1-opt restoration, and caps accepted pair moves at n per call. It never accepts a worsening original-objective move.

The normative identities are: f_ab=min(0,h_v+q_vi a+q_vj b); offset += f00; h_i += f10-f00; h_j += f01-f00; q_ij += f11-f10-f01+f00; restore x_v=1[h_v+q_vi x_i+q_vj x_j<0]. For d_i=1-2x_i, pair delta is Δ_i+Δ_j+q_ij d_i d_j. Leaf/isolated elimination uses the corresponding two/one-entry table. The mutable hypothesis notes explain these identities but do not govern this frozen protocol. Every elimination is exact in binary arithmetic for the small integer coefficients used here. Tie choices are deterministic (zero for eliminated-bit ties, lowest variable indices otherwise). No diagonal truncation, rounding or heuristic fixing is allowed.

## Baseline and frozen instances

Call the unchanged public `UltimateSolver::solve()` from the release library built at source commit fdec0df; raw returned energy is recorded before the common full-variable restoration, so its contribution is visible. The primary baseline is explicitly Ultimate plus this common restoration, not an assertion that its raw return is all-variable 1-opt. Use fixed seed, one slice, one population, two temperatures, 64 physical lanes per temperature, sweeps_per_exchange=1, temperature endpoints 20 and 0.2. QPBO, probing, incumbent and 1-opt remain active. This explicitly configured baseline is not a claim about the best possible tuning of Ultimate. Changing the public num_replicas field does not resize lanes.

Five generated families: weighted signed cycle; subdivided cubic core (core n/4, cycle plus opposite matching, insert exactly two new degree-2 vertices on EACH core edge); sparse signed Erdos-Renyi (edge probability min(6/(n-1),1)); dense signed Erdos-Renyi (probability 1/2); same sparse construction with integer Ising fields in [-2,2]. Edge weights are independent signed magnitudes 1..5, generator deterministic SplitMix64. All are converted from E=sum J_ij s_i s_j + sum b_i s_i, s=2x-1, with full offset preserved. Exact generator source and instance fingerprints accompany raw results; no optimization of generator parameters after outcomes.

Sizes n in {16,64,128}; instance seeds {1101,1102,1103}; solver seeds {2101,2102,2103,2104,2105}. Fixed-sweep mode uses exchanges in {1,8}. There are 5×3×3×5×2×8=3600 rows. Arm order is cyclically permuted by seed and rung, reversed on alternating instance/seed parity to distribute drift. No parallel benchmark runs; RAYON_NUM_THREADS=1. One separate process per row permits per-run peak RSS and user/system CPU measurement via /usr/bin/time. Process launch, common generator, reference-target construction and final independent audit are outside algorithm wall time and listed separately; transformations, mapping, final refinement and incumbent handling are inside.

## Matched wall experiment and honest timing limits

All five families, n=128, same three instance seeds and five solver seeds, all eight arms, fixed 100ms search budget: 600 rows. Transform once per run, then repeatedly call the same unchanged Ultimate solver for one exchange, seed = solver_seed.wrapping_add(restart_index × 0x9e3779b97f4a7c15). The first restart index is zero, so fixed and wall modes share their first call seed. Include transform/lift/refinement in elapsed algorithm time. Execution order is transform once → deadline check → solve → lift → common full-variable 1-opt → optional C → incumbent/target observation → deadline check. Always finish this atomic unit; report overshoot. If the residual graph is empty, skip Ultimate and obtain its exact solution by lifting the empty vector, but still execute and account the common refinement and observations; subsequent units repeat until the common deadline (no candidate-only early stop). Only rows within 5% of the common budget license a matched-time comparison; an instance/seed comparison requires all compared arms valid. Report exclusions and both filtered/unfiltered descriptive results. If no valid comparisons remain, verdict is instrument-inconclusive, never a win. Transformation alone exhausting the budget must return a valid lifted initialization and be marked overrun; never silently extend an unbounded search.

Before this registration the existing host calibration ran on G1 (not RC021 or G11 sentinel): windows 8,32; pairs 6; reps 8; injection 25%; no pin; one thread. See calibration.tsv. Null medians -5.44%/-3.84% and substantial tails; +25% injection measured +21.34%/+15.91%. This short calibration detects gross effects but does not establish fine-resolution timing. Timing is exploratory, not an entitled production speed claim. Freeze **25%** as the minimum timing signal worth an independent follow-up, with a mandatory null arm in that follow-up. A small positive ratio is not promoted. No perf change to engine.rs/types.rs is made or claimed.

## Targets and metrics

For n=16, compute optimum by a separate exhaustive original-edge scorer before benchmarking. For larger instances, use a feasible reference target from an independent baseline call (64 exchanges, seed 9001), score canonically and store its solution/fingerprint. These are fixed targets, not optima or candidate-derived best-known values. Target construction is shared oracle work and reported separately, not solver training.

Record original energy, state bitstring/fingerprint, target, success, first observed time-to-target (null/censored on failure), time when final best was first observed, elapsed wall, process user/system time, per-process peak RSS, restart count, residual n/m, coefficient-table evaluations, degree scans, pair queries, gain scans, raw pre-common energy, common 1-opt improvement and accepted pair moves. Baseline per-kernel evaluation counts are **not exposed**: report nominal 128*n*exchanges per solve as an upper bound before clamping, not exact counted total work. Expose this missing cost dimension explicitly. Fixed sweeps alone never license an equal-cost claim. Algorithm-time observations are at solver return/refinement boundaries, so they upper-bound finer internal time-to-best/target. GPU cost is zero; GPU comparison is unavailable, not inferred.

Quality gap uses (E-E_target)/max(1,abs(E_target)); negative values mean beating a feasible target, not negative optimality gap. Report per-family/size means, medians, seed variance, success probability, paired win/tie/loss and time/CPU/RSS distributions. Failed target times are censored, never dropped to manufacture a faster mean. Confidence summaries, if used, resample instance clusters rather than treating repeated seeds as independent instances. With only three instance seeds, external generalization remains weak. Do not search for significant subgroups after outcomes.

## Checks, anomalies and decisions

Before real rows: exhaustive small mixed-field reduction/lifting equivalence for every residual assignment; pair-flip Δ vs recomputed energy for all pairs; C never-worse and genuine barrier counterexample where every single flip fails; null transform exact identity; absent eligible vertices does no elimination; deterministic replay; exhaustive gauge counterexample. Test integer and non-integer correctness models separately; numeric tolerance 1e-9 scale on non-integer checks. No timing assertion in tests.

Primary comparisons are A+B (mask 3) vs baseline (mask 0) for H01, and C (mask 4) vs baseline for H07, in the matched-wall suite. All other contrasts, including A+B+C, and both fixed-sweep rungs are descriptive ablations only. No selecting an arm or a rung after outcomes.

For each family, retain an instance/seed block only when ALL eight arms have elapsed in [95,105]ms. Each of the three instance seeds must retain at least three solver seeds; otherwise the family is instrument-inconclusive. For each instance compute mean paired quality advantage (E_baseline-E_candidate)/max(1,abs(target)) over retained seeds. Family effect is the mean of its three instance means. For timing use restricted mean observed time-to-target at horizon 100ms: success time clipped to 100ms; every failure or first target observation after the horizon contributes 100ms. Average within instance then equally across three instances; this includes censoring and is NOT the mean among successful runs. Total elapsed is not the speed endpoint in equal-wall mode.

A family passes a continuation screen if either quality advantage ≥0.01 with positive advantage in every instance, or candidate/baseline restricted target-time ratio ≤0.75 with no worse mean final energy in any instance. H01 additionally requires residual n smaller than original n on every instance. H01/H07 continue only if their respective primary comparison passes on at least one of the four predeclared non-cycle families. Cycle-only success is a known exact-method positive control. These five-family screens are exploratory prioritization, not multiplicity-corrected discovery or external generalization. Mixed signs/insufficient valid rows do not pass. If eligible data exist but no primary contrast passes, ARCHIVE the mechanism as currently immaterial; preserve what the barrier census taught. An instrument-inconclusive family is not a negative scientific result. Failing the criterion does not authorize retuning this experiment.

Every ≥25% unexpected advantage requires objective, target, budget, seed replay and adversarial-family inspection before extending functionality. A+B+C beating baseline while C fails alone is an interaction to analyze, not a license to attribute gains to C. Incomplete/failed rows are recorded, never silently rerun. A technical failure before candidate data requires a prospective separate amendment. After data, subsequent tests get new numbered protocols, never edits here.
